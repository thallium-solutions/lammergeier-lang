# Lammergeier Lang — website

A single-page static site that ships the language's documentation with
client-side search and lammergeier-themed visuals. No build tool, no
dependencies at runtime beyond two CDN-hosted libraries (`marked` for
Markdown and `highlight.js` for code highlighting).

## Layout

```
website/
├── index.html                 # single-page app shell
├── build.sh                   # copies docs/ → content/, sitemap lastmod (idempotent)
├── publish.sh                 # bunny.net upload + CDN purge
├── .bunny-token               # bunny.net API key (git-ignored, not in the repo)
├── README.md                  # this file
├── assets/
│   ├── css/main.css           # theme + layout
│   ├── js/app.js              # hash router, renderer, search
│   └── images/                # logo + mascotte (copied from ../images)
└── content/                   # generated by build.sh — do not edit directly
    ├── SYNTAX.md              #   source-of-truth lives in docs/ and
    ├── TRANSPILATION.md       #   is copied here so the site can be
    ├── stdlib.md              #   deployed standalone.
    ├── libraries.md
    ├── server_plugins.md
    ├── third_party_libraries.md
    ├── installation.md
    ├── package_manager.md
    ├── README.md
    └── CONTRIBUTING.md
```

## Rebuild after editing docs

```bash
./website/build.sh
```

The script copies every Markdown file it needs from `docs/` and the
project root into `website/content/`, then rewrites cross-doc links
(`SYNTAX.md` → `#/docs/syntax` inside the SPA, repo-internal paths like
`../lib/foo.lam` → absolute GitHub URLs).

## Local preview

```bash
python3 -m http.server --directory website 8765
```

Open <http://localhost:8765/>. The hash-based router means deep links
like `#/docs/stdlib?h=lamdata` work out of the box — no server-side
routing required.

## Deployment

Production is a bunny.net storage zone (`lammergeier-lang-website-production`)
behind the pull zone `production-lammergeier-lang` (lammergeier-lang.dev):

```bash
./website/build.sh               # refresh content/ and sitemap.xml
./website/publish.sh --dry-run   # show what would be deleted and uploaded
./website/publish.sh             # publish and purge the CDN cache
```

**What `publish.sh` does:**

1. Deletes everything in the storage zone.
2. Uploads `assets/`, `content/`, `index.html`, `robots.txt` and
   `sitemap.xml`, each with its SHA-256 so bunny.net rejects corrupted
   uploads.
3. Purges the pull zone's cache.

**Safety checks.** It refuses to run when `content/` is older than its
sources (run `build.sh`). It also refuses when the pull zone does not serve
that storage zone. Zones are matched by exact name, because the API key
sees every zone of the account.

**API key.** `publish.sh` reads the bunny.net account API key from
`BUNNY_API_KEY`, or from `website/.bunny-token`:

- the file is git-ignored and must stay so; the script refuses to use it
  otherwise and keeps it at mode 600;
- the key is passed to `curl` through a private temporary header file,
  never on the command line.

**On releases.** A new compiler release published with
`./mirror-to-github.py` runs `build.sh` and `publish.sh` automatically
(`--no-website` skips it).

**Search engines.** `build.sh` sets `<lastmod>` in `sitemap.xml` to the last
commit that touched the docs or the site. The doc pages are hash routes
(`/#/docs/...`): search engines index them as the home page. Separate
pages in search results would need path-based routes.

## Search

The search index is built client-side on first focus of the search
box. Each doc is split on its H2/H3/H4 headings so results link
straight to the relevant section via the hash router's `?h=<slug>`
parameter. Nothing is pre-compiled; if the docs grow substantially
this can be swapped for a pre-built JSON index without changing the
HTML.

## Theme

Colour palette tracks the project logo: slate-indigo surfaces,
bone-ivory text, ochre/amber accents. Typography uses the system sans
stack for body text and a Palatino-style serif for headings. The CSS
stays in a single file (`assets/css/main.css`) so it's easy to read
and fork.
